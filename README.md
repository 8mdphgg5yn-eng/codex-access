# 开控：Codex 无鼠标操作原型

面向上肢活动受限使用者的本机实验项目，暂名“开控”。首版验证输入、纠错、授权、停止和查看结果能否不用鼠标完成。它还不是经目标使用者验收的辅助技术产品。

首个公开版本为 **v0.1.0-alpha.1**，供本机样本试用和反馈，尚未经过目标使用者验收。下载见 [预发布版本](https://github.com/8mdphgg5yn-eng/codex-access/releases/tag/v0.1.0-alpha.1)，问题反馈见 [Issues](https://github.com/8mdphgg5yn-eng/codex-access/issues)。已知限制及后续工作见 [KNOWN_ISSUES.md](KNOWN_ISSUES.md)。

本项目自有代码采用 MIT，署名 Mgb，使用 OpenAI Codex 协助开发与核对；这是独立项目，不是 OpenAI 官方客户端。没有复制 Voice Relay 或 agent-voice-mcp 的实现。运行时调用的 Codex、浏览器和系统语音分别适用其自身条款。

## 启动

需要已有 Node.js 22 或更新版本。无需安装 npm 依赖。

从 Release 下载并解压 `codex-access-v0.1.0-alpha.1.zip`，进入解压目录；也可获取源码：

```sh
git clone https://github.com/8mdphgg5yn-eng/codex-access.git
cd codex-access
git checkout v0.1.0-alpha.1
```

双击本目录的 `start.command`；或在本目录运行：

```sh
node server.mjs
```

打开 <http://127.0.0.1:8782>。服务只监听 IPv4 本机回环地址。启动器会打开默认浏览器；首次系统提示仍须由使用者处理，这部分没有完成无障碍独立安装验收。保留服务终端，Control+C 关闭。端口占用时可设置 `CODEX_ACCESS_PORT`，不会改动系统网络配置。

默认是练习模式，不需要 Codex 登录，不调用模型，也不执行输入的要求。它只演练草稿确认、固定授权、停止和结果回显，页面及结果都明确标识。先在练习模式熟悉操作，再选择真实模式。

## 键盘操作

| 按键 | 行为 |
| --- | --- |
| Tab、Shift+Tab | 按浏览器顺序切换控件 |
| Enter、空格 | 执行当前按钮；输入框中的 Enter 不会发送 |
| F6 | 定位下一个可用控件，包括输入框和结果区 |
| F7 | 执行当前聚焦的按钮 |
| F8 | 直接定位结果区 |
| F9 | 直接返回任务输入 |
| Esc | 有任务时请求停止；仅有发送确认时取消确认并返回草稿 |

部分键盘需配合 Fn。输入法正在组词时，按键可能先由输入法处理；可使用停止按钮。快捷键不是全局热键，只在网页获得键盘输入时生效。

草稿支持普通键盘编辑、查找并替换首处、按标点删除上一句、清空及撤销。删除上一句是有限的标点拆分，不是语义判断。查找字段按字面匹配，重复文字会告知数量，仅替换第一处。草稿不会因停顿自动发送。

“单键扫描与测试目录”中可以开启动作按钮扫描，按空格执行当前高亮按钮，间隔可调。扫描不自动执行操作，编辑文字时暂停。当前只扫描动作按钮；任意文本输入和下拉选择仍需键盘、系统听写或其他辅助技术，不能据此宣称已支持仅一个辅助开关独立完成所有任务。真实辅助开关映射尚未验收。

系统听写可以作为输入候选，首版没有自带录音、STT 或语音控制服务。结果朗读使用浏览器或系统语音，是否联网、中文发音与回声行为未实测。停止朗读与停止任务是不同动作；Esc 会同时尝试停止朗读并按任务状态请求中断。

## 一次完整练习

1. 输入一条草稿，或者定位“填入练习句”并执行。
2. 在查找与替换框纠正一个词，核对草稿；需要时撤销。
3. 执行“检查草稿并发送”。焦点停在“返回修改”，确认内容后再定位“授权并发送这份草稿”。
4. 出现练习授权，焦点优先停在“拒绝本次”。选择允许或拒绝。没有自动同意倒计时。
5. 允许后约 5.6 秒完成固定演练。期间可按 Esc 停止；停止后迟到计时器不会把它改成完成。
6. 任务结束后可用 F8 查看结果，也可定位“定位到结果”。结果区可键盘滚动、选中和复制。

## 真实 Codex 模式

需要已安装并已在原客户端登录的 `codex` 命令。原型不代为安装、登录或搜取密钥，不读取或复制凭证文件。它启动 Codex 子进程，由 Codex 使用自己的认证机制。`CODEX_ACCESS_BIN` 可以指定已有 CLI 的路径。已实测 CLI 0.160.0；其他版本需重新验证。

“检查 Codex 连接”执行协议初始化及账号可用性读取，不开始模型任务。选择真实模式后，检查草稿并授权发送才发起任务。工作目录固定为本项目 `workspace/`，其中仅有自制样本。上一个真实会话在当前网页会话中复用；关闭 Codex 连接后重新建立。Codex 会话请求 ephemeral，不依赖原有聊天历史；仍不能由此断言服务端不留存记录。

本机 0.160.0 生成的 schema 仍列出 `untrusted`，但实际启动已拒绝该配置。本版采用实际可启动的 `on-request`、人工审核和 `workspace-write`，不使用 `never` 或完全访问。若 thread/start 返回的策略与要求不一致，原型不发出 turn/start。目录内读写可能按 Codex 策略直接进行，不能将“人工审核”解释为每条命令、每次文件修改都询问。

原型处理真实命令授权与文件修改授权，仅提供允许本次、拒绝本次，不创建永久规则或整会话自动同意。详情来自原始请求及文件变更，不交给第二个模型改写。其他尚未实现的交互请求会被拒绝，并请求停止任务，界面和记录会说明；第一版不承诺完整支持所有 Codex 工具与澄清形式。

停止过程区分请求已发出、等待中断回执、已确认中断及连接中断后状态未知。收到 turn/completed 的 interrupted 才显示 Codex 确认中断。若任务先完成，会显示实际完成状态；关闭连接不等于回滚文件。页面失联一段时间后，服务会请求停止并关闭该页面的子连接，防止遗留无人操作的控制会话，但这不是断网情况下的任务回滚保证。

## 数据与范围

- 页面无远程字体、统计、Cookie 或 localStorage。草稿和网页会话放在内存，刷新或退出不保证恢复。结果按纯文本显示，不执行模型返回的 HTML。
- 不在应用日志中打印草稿或凭证。Codex 子进程的 stderr 不转发到浏览器或普通终端。Codex 本身及服务提供方的上下文、日志和留存设置仍适用，不能保证整个任务只外发草稿、完全离线或不产生记录。
- 启动时按进程要求关闭连接器、插件、hooks、记忆、浏览器与电脑操作、多代理等功能，并清空自定义 MCP 配置；没有改动用户全局配置。这不是完整的工具隔离与安全审计结论。
- `workspace-write` 主要限制写入，不是对其他目录的完整读取隔离。首版只用于自制样本，不用于真实案卷或敏感文件。
- 本机接口校验 Host、Origin 和每页随机令牌；静态服务采用允许列表，不提供代码、测试目录、工作文件或凭证下载接口。令牌只用于当前页面的本机控制，不是 Codex 账号凭证。

## 开发与核对

```sh
npm test
node --check public/app.js
node --check server.mjs
```

自动测试使用固定协议进程与假时钟，验证重复发送、过期授权、拒绝与允许、中断回执、迟到结果、准备期间停止、沙箱策略不一致，以及本机接口边界。它不证明真实语音准确率或真实使用者易用性。

真实检查必须显式执行，会使用已登录 Codex 的额度，只发送自编测试文本：

```sh
node tests/live-smoke.mjs --run
node tests/live-control.mjs --run
```

live-control 只允许一个固定打印命令及其已经核对的 shell 包装，遇到其他授权一律拒绝；另用 `sleep 20` 验证中断。检查结果含自编提示与输出，保存于 `evidence/`，不纳入默认版本控制。不要改成真实材料回归或任意命令自动同意。

本轮通过情况、实际失败修正及未验收范围见 [CHECKS.md](CHECKS.md)。架构采用 [官方 Codex App Server 协议](https://learn.chatgpt.com/docs/app-server)；该接口仍有实验性和版本维护成本。首版没有复制桌面应用的全部工具、安装、认证和无障碍能力。
